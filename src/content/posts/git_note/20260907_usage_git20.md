常用在遠端 Repo 有更新且操作環境不同的狀況下

可以用`git pull` 來將最新的 Repo 拉到本機 

像是我自己，我會用公司跟家裡的電腦進行更改這個blog的動作

我如果在公司有寫一些，且`git push`到雲端了

那我回到家的時候就要使用`git pull`來更新我家裡電腦的資料

---

當我執行`git clone`時，是可以直接使用`git pull`的

因為`git clone`的時候 Git 已經自動幫你設定好了

但當我今天是用`git init`，就需要多這一步設定

[第一次使用 `git pull`](/blog/posts/git_note/20260802_usage_git4/#5-%E4%B8%8A%E5%82%B3%E5%88%B0%E9%81%A0%E7%AB%AF---git-push)

`git init` -> `git push -u origin main`

`-u` 很重要，就是讓Git記住**本機 main** 對應 **origin 的 main**

因為有設定這個`-u`，所以之後可以直接使用`git pull`

不然可是會每次都要打`git pull origin main`呢

---

### `git pull` 跟 `git pull origin main` 差異

`git pull`：依照目前已經設定好的對應關係，從遠端抓更新回來

`git pull origin main`：從 origin 這個遠端 Repo 的 main 抓更新回來

平時已經設定好對應關係時，就可以用`git pull`，這樣子最方便

如果 Git 還不知道要從哪個遠端、哪個 Branch 抓，或是想明確指定，就可以用：

`git pull origin main`
