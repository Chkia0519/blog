### 查詢 HEAD 移動過的位置

`git reflog` -> 查看 HEAD 曾經移動過哪些位置

`git log` -> 查看 Commit 歷史

執行`git reflog`，會看到範例如下：

```
a1b2c3d HEAD@{0}: reset: moving to HEAD~1
f6e7d8c HEAD@{1}: commit: 完成登入功能
c3d4e5f HEAD@{2}: commit: 初始化專案
```

`f6e7d8c` -> 當時 HEAD 指向的 Commit ID

`HEAD@{1}` -> HEAD 上一次待的位置

`commit: 完成登入功能` -> 當時做了什麼操作

`git reflog`常用在用`git reset --hard HEAD~1`反悔的時候

當你執行reset的時候，用`git log`就會查不到資料

這時候要用`git reflog`才查的到

---

### 找到位置後，怎麼移動回去

例如我要回到上面範例的`f6e7d8c`

這時候就可以執行`git reset --模式 f6e7d8c`

也可以直接用`git reset --模式 HEAD@{1}`

因為`HEAD@{1}`就是`f6e7d8c`

但通常這個情境是要救回剛剛不小心被 reset 移出目前分支歷史的 Commit

所以一般會用`git reset --hard HEAD@{1}`，讓 HEAD、暫存區及工作目錄都恢復到`HEAD@{1}`的狀態

| 模式 | HEAD | 暫存區 | 工作目錄 |
|------|------|------|------|
|`--soft`| 回到`HEAD@{1}` | 保留目前內容 | 保留目前內容 |
|`--mixed`| 回到`HEAD@{1}` | 變成`HEAD@{1}`的狀態 | 保留目前內容 |
|`--hard`| 回到`HEAD@{1}` | 變成`HEAD@{1}` | 變成`HEAD@{1}` |


>[!TIP]
> `HEAD@{1}`的編號會隨著後續 HEAD 操作而改變
> 
> 如果已經確認要回復哪一個 Commit，使用 Commit ID（例如範例的`f6e7d8c`）會更明確
