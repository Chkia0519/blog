`git restore` 是什麼？

主要用來處理兩種情況：

1. 放棄工作目錄中的修改
2. 取消已經執行的 `git add`

restore = 恢復、還原的意思，也就是使用某個來源的內容，覆蓋目前的檔案狀態



>![!TIP]
> `git restore` 不只有一種用法，不同參數會決定它是在**放棄修改**，還是在**取消暫存**

---

### 放棄檔案中尚未 git add 的修改

　　也就是用暫存區的版本覆蓋工作目錄的版本

　　如果目前工作目錄有更動，但是還沒有`git add`

　　這時候執行`git restore <檔案名稱>`，工作目錄中的檔案會被還原成暫存區中的版本

　　當暫存區沒有新修改時，`git restore <檔案>` 會將檔案恢復成最新一次 Commit（HEAD）的狀態

　　若暫存區已有已暫存的修改時，`git restore <檔案>` 會將工作目錄中的檔案恢復成暫存區的狀態

　　在執行前可以透過[`git diff <檔案>`](/blog/posts/git_note/20260815_usage_git13/)，來確認修改內容真的不需要，再執行`git restore <檔案>`

**git restore <檔案> 主要用來還原已被 Git 追蹤的檔案，如果是新建的檔案，還沒被追蹤就不在此限**

>![!TIP]
>`git restore <檔案名稱>`，檔案名稱通常會寫成相對路徑
>
>路徑中如果有空格，需要使用引號 例如： "my files/index.html"

---

### 放棄目前目錄中的所有未暫存修改

　　`git restore .` . = 目前所在目錄

　　這個指令會將目前目錄及子目錄中，所有已追蹤檔案的未暫存修改恢復成暫存區的狀態

　　可以理解為一次對多個檔案執行 `git restore <檔案>`

　　git restore .：

- 不會取消已經 git add 的修改
- 不會刪除未追蹤的新檔案
- 只會還原目前目錄及子目錄中的已追蹤檔案
- 未暫存修改被捨棄後，通常**無法透過 Git 找回**

　　執行前最好先檢查：`git status`、`git diff`

---

### 取消`git add`，但會保留工作目錄

　　`git restore --staged <檔案>`

　　這個指令會取消`git add`的狀態，但不會將工作目錄還原成暫存區

　　本質上是將暫存區恢復成 HEAD 的狀態

　　在 Commit 前發現 add 錯檔案時，就可以用`git restore --staged <檔案>`


---

### 取消所有已`git add`的修改

`git restore --staged .` . = 目前所在目錄

　　將目前目錄及子目錄內**所有**已加入暫存區的修改移出暫存區，但保留工作目錄中的修改

---

對照表格

| 程式碼 | 狀態 |
|------|------|
|`git restore <檔案>`|放棄**單一檔案**未暫存修改|
|`git restore .`| 放棄**所有**未暫存修改 |
|`git restore --staged <檔案>`|取消單一檔案的 git add|
|`git restore --staged .`|取消所有 git add，但保留修改|
