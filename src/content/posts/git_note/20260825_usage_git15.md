`git revert` 

- 不會刪除原本的 Commit
- 不會改寫歷史紀錄，只會新增反向資料
- 會建立新的 Commit
- 適合已經 Push 到遠端的 Commit

---

會根據指定 Commit 的修改內容，嘗試建立一個新的反向 Commit，用來抵消該 Commit 的效果

大多都可以執行反向，但也是有可能會有無法作反向操作的時候，這個部分就後續再補

意思就是 Git 會將指定 Commit 的新增、刪除等操作反向執行，並建立一個新的 Commit

不會刪除原本的 Commit，而是透過新增一個反向 Commit 來抵消指定 Commit 的效果

例如：

```text
Commit C：

+ Hello
```

執行：

```bash
git revert C
```

Git 會建立新的 Commit：

```text
- Hello
```

因此：

```text
Commit C：新增 Hello
Revert Commit：移除 Hello
```

兩者的效果互相抵消。

---

### 甚麼情況下會用到`git revert`

當錯誤的 Commit 已經提交到遠端儲存庫，已經被其他人拉取時，

通常不建議使用 [`git reset`](/blog/posts/git_note/20260814_usage_git12/) 修改歷史。

這時候就可以使用 `git revert`，

透過建立新的反向 Commit 來保留歷史紀錄，

同時撤銷指定 Commit 的效果。

---

實際操作演練：

在使用`git revert`之前，需要先取得要撤銷的 Commit ID

這時候就要使用[`git log --oneline`](/blog/posts/git_note/20260804_usage_git6/#2簡潔查詢---git-log---oneline)，來查看 Commit 的歷史紀錄

取得要撤銷的 Commit ID 之後就可以執行`git revert <Commit ID>`

例如：
```
d544e58 diff OK
ae35e5e log 學習筆記
d1a1c55 diff筆記
```

我要撤銷 d544e58 ，所以我執行`git revert d544e58`

執行之後就會產生一筆反向的資料

這個時候可以再執行一次`git log --oneline`

會看到：
```
s84fdr5 Revert "diff OK"
d544e58 diff OK
ae35e5e log 學習筆記
```

從這邊可以看到：

- 原本的 Commit 還在
- 且 Git 新增了一筆 Revert Commit
- 歷史紀錄沒有被刪除

---

### `git restore`、`git reset`、`git revert` 差異比較表

| 程式碼 | 用途 |
|------|------|
|[`git restore`](/blog/posts/git_note/20260821_usage_git14/)| 還原檔案內容、取消暫存 |
|[`git reset`](/blog/posts/git_note/20260814_usage_git12/)| 移動 HEAD，可能會改變歷史 |
|`git revert`| 建立新的反向 Commit 來撤銷修改 |
