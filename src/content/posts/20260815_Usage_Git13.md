### 比較工作目錄 & 暫存區 - `git diff`

　　`git diff` -> 查看**還沒** git add 的修改

　　`git diff` = 比較的是**工作目錄**與**暫存區**之間，有哪些地方不一樣

　　通常會和`git status`一起做使用

　　先用`git status`查看目前的狀況，再用`git diff`查看到底改了些甚麼

　　如果我現在已經`git add`的話，執行`git diff`就會甚麼都看不到

　　因為工作目錄和暫存區現在沒有差異，所以不會出現任何東西

---

### 比較暫存區 & 最新 Commit - `git diff --staged`

　　`git diff --staged` 和 `git diff --cached` 效果一樣 -> 查看**已經** git add 的修改

　　如果我已經執行`git add`，我可以用它們查看目前 add 的項目與最新的 Commit (HEAD) 的差異

　　很適合用在 Commit 前先確認等等到底會提交什麼

---

### 看目前所有還沒 Commit 的修改 - `git diff HEAD`

　　`git diff HEAD` -> 不管有沒有`git add`，只要還沒 Commit，都可以透過`git diff HEAD` 查看

　　它包含：

- 已修改但還沒有 `git add` 的內容
- 已經 `git add` 但還沒有 Commit 的內容

　　比較目前工作目錄與 HEAD 的差異，結果同時包含已暫存及未暫存的修改

---

### 比較兩個 Commit 的差異

- `git diff <Commit-A> <Commit-B>`

　　以 A 為基準，查看 B 修改了甚麼
 
　　在diff後方輸入要比較的兩個 Commit ID 就可以兩個 Commit 之間的內容到底差在哪裡

- `git diff HEAD~1 HEAD`

　　HEAD：目前最新的 Commit

　　HEAD~1：最新 Commit 的前一個 Commit

　　意思是：比較最新 Commit 與前一個 Commit

　　也就是：**查看最新一次 Commit 修改了哪些內容**

>[!TIP]
> 其中`git diff HEAD~1 HEAD`，`HEAD~1` = `HEAD~n` n 可改為其他數字
>
> 意思是：比較最新 Commit 與往前數n層的那一個 Commit，兩個之間的差異

---

### 比較兩個 Commit 特定檔案的差異

　　`git diff <Commit-A> <Commit-B> -- <檔案路徑>`

　　-- 用來區隔 Commit 與檔案路徑

　　一般可使用相對於目前所在目錄的路徑；如果在儲存庫根目錄執行，就是從儲存庫根目錄開始

　　範例：`git diff HEAD~1 HEAD -- index.html`

　　意思是：顯示 index.html 在最近一次 Commit 中的修改。

---

### 只查看哪些檔案有改變 

　　`git diff --name-only`

　　比較工作目錄與暫存區，只列出尚未 git add 的變更檔案名稱

　　也可以在`--name-only `後面加入`<Commit-A> <Commit-B>`來做查詢

　　**只查看尚未 git add 的變更檔案名稱，不顯示實際修改內容**

---

### 查看檔案的變更狀態

　　`git diff --name-status`

　　查詢出來在檔案的前面的英文字母就代表檔案狀態：

　　A = Added 新增檔案

　　M = Modified 修改檔案

　　D = Deleted 刪除檔案

　　R = Renamed 重新命名檔案

　　一樣可以指定`<Commit-A> <Commit-B>`來做查詢

---

### 查看修改行數統計

　　`git diff --stat`

　　適合快速查看：

- 哪些檔案有修改

- 每個檔案大約修改多少內容

- 新增與刪除了多少行

---

`git diff --name-only`、`git diff --name-status`、`git diff --stat`

都可以加上`--staged`、`HEAD`、`HEAD~1 HEAD`、`<Commit-A> <Commit-B>`，來做比較

| 語法 | 比較範圍 | 比較對象 |
|------|------|------|
|`git diff`| 還沒有 git add | 暫存區 ↔ 工作目錄 |
|`git diff --staged`| 已經 git add | HEAD ↔ 暫存區 |
|`git diff HEAD`| 所有尚未 Commit | HEAD ↔ 工作目錄 |
|`git diff HEAD~1 HEAD`| 最新 Commit 與前一個 Commit | HEAD~1 ↔ HEAD |
|`git diff <Commit-A> <Commit-B>`| 兩個 Commit 間 | A ↔ B |


---

### 如何閱讀 git diff 輸出的內容

　　範例：
```
diff --git a/index.html b/index.html
index 1234567..89abcde 100644
--- a/index.html  -> 比較前的舊版本檔案
+++ b/index.html  -> 比較後的新版本檔案
@@ -1,3 +1,4 @@
 <h1>Hello</h1>
-<p>舊內容</p> -> - 代表舊版本中有，但新版本中被刪除的內容
+<p>新內容</p> -> + 代表新版本增加的內容
+<button>登入</button>
```

　　`@@ -1,3 +1,4 @@`意思：

　　-1,3 -> 代表舊版本從第 1 行開始，顯示 3 行

　　+1,4 -> 代表新版本從第 1 行開始，顯示 4 行

　　**Git 預設會產生 patch 格式的差異內容，並顯示修改位置附近的上下文**

---

### 調整顯示的上下文行數

　　`git diff -U5` 

　　`-U5` 代表在修改內容的前後，各顯示前後 5 行，方便判斷修改位置

　　沒有設定時，Git 預設顯示修改位置附近 3 行上下文

　　例如：

```
# 顯示前後 1 行
git diff -U1

# 顯示前後 10 行
git diff -U10

# Commit 之間也能使用
git diff -U5 HEAD~1 HEAD
```

---

### 完全忽略空白的有無與數量

　　有時候只是調整縮排或空格，卻讓 git diff 顯示很多不重要的修改，這時候可以使用

　　`git diff -w`、`git diff --ignore-all-space`

　　這兩個指令效果相同，會在比較內容時**忽略所有空白的新增、刪除及數量變化**，讓輸出的結果更容易閱讀

---

### 忽略空白數量的變化

　　`git diff -b`、`git diff --ignore-space-change`

　　會忽略空白數量的變化，但不會完全忽略所有空白

　　把連續一個以上的空白視為相同，也會忽略行尾空白

　　例如：
```
修改前：
hello world

修改後：
hello     world
```

　　因為原本中間就有空白，只是從1個空白 -> 5個空白，所以執行`git diff -b`不會顯示差異

　　但是以下狀況就不相同：
```
修改前：
helloworld

修改後：
hello world
```

　　像這個狀態，因為原本兩個單字之間完全沒有空白，修改後才新增空白

　　這不只是空白數量改變，而是從**沒有**變成**有**

　　這種狀況下的就會顯示差異

---

　　`-b` 較保守：只忽略空白數量的變化(可以有空白，但不在意空白有幾個)

　　`-w` 範圍較大：完全忽略所有空白

　　實務建議：平常先使用 `-b`，遇到大量純格式調整時再使用 `-w`

> [!WARNING]
>如果使用 Python 等對縮排敏感的程式語言
>
>`-w` 可能會隱藏具有實際影響的縮排修改，需要小心使用

---

### 以單字為單位查看修改

　　`git diff --word-diff`

　　一般 git diff 是以**行**為單位顯示差異，可以用`--word-diff`改成以**單字**為單位顯示

　　適合查看：

- Markdown
- 說明文件
- 一整行很長的文字
- 只更改少數單字的內容

　　可以搭配`--color-words`透過顏色標示單字，更易閱讀哪裡有異動

---

>[!TIP]
> `git diff` 不會顯示尚未被 Git 追蹤的新檔案，未追蹤檔案要先透過 `git status` 查看
>
> 執行 `git add` 後，才能使用 `git diff --staged` 查看它即將提交的內容。
