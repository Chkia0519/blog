`git reset` = 把目前分支和 HEAD 移動到指定的 Commit

可以解釋成做時光機回到過去(?)

但 `git reset` 會影響 Commit、暫存區，某些模式還會刪除尚未提交的修改

所以要慎重使用

---

### 取消 Commit、取消暫存，但保留修改內容 - `git reset --mixed`

　　當我執行`git reset --mixed HEAD~1`

　　就會從目前的 C 退回至 B ， C 的修改內容**不會消失**，但會從暫存區退回到工作目錄

　　也就是取消已經`git add`的動作，但會保留修改內容

> [!TIP]
> `--mixed`是**reset的預設模式**
> 
> 所以執行`git reset HEAD~1`就是執行`git reset --mixed HEAD~1`

---

### 取消 Commit，修改保留在暫存區 - `git reset --soft`

　　假設目前的 Commit 如下：

```
A → B → C
        ↑
      HEAD
```

　　當我執行`git reset --soft HEAD~1`

　　就會從目前的 C 退回至 B ， C 的修改內容**不會消失**，而是會**保留至暫存區**

　　也可以理解為取消最近一次 Commit，但保留已經 git add 好的狀態

> [!TIP]
> 很適合用在：Commit 時要提交的訊息寫錯了，想取消這次的提交重新寫

---

## 風險最高的模式

### 取消 Commit，也會直接刪除尚未提交的修改 - `git reset --hard`

　　當我執行`git reset --hard HEAD~1`

　　就會從目前的 C 退回至 B

　　C 這筆 Commit 會從目前分支的歷史中移除，C 的修改內容也不會保留在暫存區或工作目錄

　　等於 Git 已追蹤的檔案會直接恢復成 B 這筆 Commit 當時的狀態

　　這主要影響 Git 已追蹤的檔案，如果新的檔案尚未被 Git 追蹤通常不受影響

> [!WARNING]
> `--hard` 會丟棄已追蹤檔案中尚未提交的修改，使用前建議先執行 `git status` 確認
