`git reset` = 將目前分支移動到指定的 Commit，且 HEAD 也會跟著移動到新的位置

可以解釋成做時光機回到過去(?)

但 `git reset` 會影響 Commit、暫存區，某些模式還會刪除尚未提交的修改

所以要慎重使用

---

### 取消 Commit、取消暫存，但保留修改內容 - `git reset --mixed`

　　當我執行`git reset --mixed HEAD~1`

　　就會從目前的 C 退回至 B ， C 的修改內容**不會消失**，但會從暫存區退回到工作目錄

　　也就是取消 `git add` 的結果，但會保留修改內容

> [!TIP]
> `--mixed`是**reset的預設模式**
> 
> 所以執行`git reset HEAD~1`就是執行`git reset --mixed HEAD~1`

---

### 取消 Commit，修改保留在暫存區 - `git reset --soft`

　　假設目前的 Commit 如下：

```
A → B → C
        ↑
      HEAD
```

　　當我執行`git reset --soft HEAD~1`

　　就會從目前的 C 退回至 B ， C 的修改內容**不會消失**，而是會**保留在暫存區**

　　也可以理解為取消最近一次 Commit，但保留已經 git add 好的狀態

　　`git reset --soft HEAD~n` = 退回 n 個 Commit，並將這 n 個 Commit 的修改保留在暫存區

　　`git reset --soft < Commit ID >` = 退回到指定 Commit ，並將這個 Commit 之後的修改都保留在暫存區

　　結論就是：

　　`--soft` 不管退回多少個 Commit ，它都會把那些被取消的 Commit 的修改全部保留在暫存區

> [!TIP]
> 很適合用在：Commit 時要提交的訊息寫錯了，想取消這次的提交重新寫
>
> 或是拿來：合併多個 Commit 重新提交

---

## 風險最高的模式

### 取消 Commit，也會直接刪除尚未提交的修改 - `git reset --hard`

　　當我執行`git reset --hard HEAD~1`

　　就會從目前的 C 退回至 B

　　C 這筆 Commit 會從目前分支的歷史中移除，C 的修改內容也不會保留在暫存區或工作目錄

　　等於 Git 已追蹤的檔案會直接恢復成 B 這筆 Commit 當時的狀態

　　這主要影響 Git 已追蹤的檔案，如果新的檔案尚未被 Git 追蹤通常不受影響

> [!WARNING]
> `--hard` 會丟棄已追蹤檔案中尚未提交的修改，使用前建議先執行 `git status` 確認
> 
> 如果真的不小心執行了，也不用太慌張
>
> 若該 Commit 還沒有被 Git 垃圾回收(GC 之後會補)，仍有機會透過 `git reflog` 找回

---

### 三種模式的比較

| 模式 | Commit（目前分支） | 暫存區 | 工作目錄 |
|------|------|------|------|
| `git reset --soft` | 回到指定 Commit | 保留 | 保留 |
| `git reset --mixed` (reset 預設模式) | 回到指定 Commit | 重設 | 保留  |
| `git reset --hard` | 回到指定 Commit | 重設 | 重設 |

- 重設 = 恢復成指定 Commit 的狀態

- 保留 = 保留目前修改內容
