Astro 是一個用來建立網站的 JavaScript 網頁框架

我會選擇 Astro，是因為它產生的網站介面簡潔、閱讀起來舒服，而且整體相對輕量，很適合拿來建立部落格

我可以用 Markdown 來撰寫文章，再透過 Astro 將 Markdown 文章轉換為靜態網站頁面

因為 Astro 可以產生靜態網站，所以可以直接在 GitHub Page 上部屬

之後我只要更新文章並將修改推送到 GitHub，就能更新部落格內容

這次建置主要是在 AI 的逐步協助下完成

雖然目前還不能完全獨立寫出整個網站，但透過實際操作，我開始了解 Markdown、Astro、GitHub、版本控制與網站部署之間的關係

未來如果有更多功能需求，也會繼續學習如何整合 React、Vue或 Svelte 等前端工具

這篇主要是我拿來記錄當時怎麼部屬 Astor 的學習記錄

---

## 第一步：確認 Node.js 和 npm

在終端機中輸入 `node v` 來確認 Node.js

在終端機中輸入 `npm -v` 來確認 npm

如果兩個指令都有出現版本的號碼，就代表已經有安裝

但是如果是出現**不是內部或外部命令**就是沒有安裝

---

這邊我就有幾個好奇的問題了

### 我不是用 Astor 來建立部落格嗎，為甚麼我需要安裝 Node.js 和 npm

Node.js 是執行環境

npm 是套件管理工具

Astro 是實際用來建立網站的框架

流程大概是這：

```
Node.js 提供執行環境
       ↓
npm 安裝及管理 Astro
       ↓
Astro 將 Markdown、版型與程式碼建置成網站
       ↓
部署到 GitHub Pages
```

- 為甚麼需要 Node.js

因為 Node.js 是一個可以讓電腦直接執行 JavaScript 的工具

在開發 Astro 網站時，Node.js 主要負責：

1. 執行 Astro 的開發工具
2. 啟動本機預覽伺服器
3. 讀取 Markdown 文章
4. 處理網頁、CSS 與圖片
5. 將專案建置成可部署的靜態網站

當我執行 `npm run dev` 就是透過 Node.js 啟動 Astro 的開發伺服器

如果沒有 Node.js，電腦就無法正常執行 Astro 的開發工具

Astro 官方也將 Node.js 列為安裝 Astro 的必要條件

- 為甚麼需要 npm

npm 是 Node Package Manager，中文稱為 **Node 套件管理工具**

Astro 本身以及網站使用的其他功能，都是一個個可以安裝的套件

npm 會幫忙：

1. 下載 Astro
2. 安裝專案需要的其他套件
3. 記錄套件版本
4. 更新或移除套件
5. 執行專案內設定好的指令

`npm create astro@latest` 

這個指令會下載並啟動 Astro 的專案建立工具，引導你建立新的網站

這也是 Astro 官方建議建立新專案的方式

如果已經有 Astro 專案，輸入`npm install`

npm 會幫忙檢查專案裡的 package.json，再把需要的套件安裝下來

他們兩個都非常重要，也難怪 Astro 會把他們列為安裝 Astro 的必要條件

## 第二步：安裝 Node.js

[Node.js 官方下載頁面](https://nodejs.org/en/download)

建議選擇：LTS，Long-Term Support，長期支援版

<img src="/blog/images/LTS.png" width="90%">

LTS 版比較適合穩定開發 Astro 專案，不必特別追求最新的 Current 版本

安裝 Node.js 時，會一起安裝 npm

執行安裝的時候要保留以下項目：

```
Node.js runtime
npm package manager
Add to PATH
```

Add to PATH 可以讓我們直接在終端機使用 node 和 npm 指令

安裝完畢之後重啟電腦，可以在cmd中輸入`node v`、`npm -v`確認是否正確安裝

### 第三步：啟動 Astro 專案建立工具

我會先創立一個我想放專案的資料夾

1. 打開終端機移動到該目錄

2. 執行`npm create astro@latest`

3. 會跳出：

```
Need to install the following packages:
create-astro@...
Ok to proceed? (y)
```

輸入 y 

4. 要把 Astro 專案建立在哪個資料夾，以及資料夾叫什麼名稱

```
dir   Where should we create your new project?
./absent-ascension
```

他會給一個 ./absent-ascension 這個是他隨機產生的名稱

.代表目前所在位置，意思就是在現在的位置建立一個名為 absent-ascension 的新資料夾

所以我一開始才會移動到我想建立的目錄，因為他預設會建立在目前所在位置

如果不想把專案建立在目前位置，可以按：Ctrl + C，離開安裝精靈

離開之後 cd 到想要的目錄再執行`npm create astro@latest`

5. 選擇 Astro 專案的初始範本

```
  tmpl   How would you like to start your new project?
         > A basic, helpful starter project (recommended)
         — Use blog template
         — Use docs (Starlight) template
         — Use minimal (empty) template
```

可以用上下鍵選擇到自己要的範本

- A basic, helpful starter project (recommended):

**一般網站**的基礎範本，會提供一些示範頁面與基本結構，方便了解 Astro 專案怎麼組成

- Use blog template

專門為**部落格**準備的範本，通常已經有文章、版面、日期、文章列表等基礎結構

- Use docs (Starlight) template

建立**技術文件**或**知識庫網站**的範本

Starlight 是 Astro 生態系中專門用來建立文件網站的工具

- Use minimal (empty) template

最精簡、接近空白的 Astro 專案，適合從0開始學習 Astro

因為我這次主要是要建立部落格，所以我選擇 Use blog template

6. 是否要立即安裝這個 Astro 專案需要的套件

選完範本之後會出現：  

```
deps   Install dependencies? (recommended)
         ● Yes  ○ No
```

這個提示就是在問有沒有需要立刻安裝套件，那當然是需要的

7. 要不要在專案中初始化 Git 版本控制

```
git   Initialize a new git repository? (optional)
         ● Yes  ○ No
```

選擇 Yes ，會再專案資料夾中建立隱藏的 .git/ 資料夾

目前只是選擇 Yes 只是先建立 Git 版本庫，還沒有上傳到 GitHub

8. 安裝完畢

```
next   Liftoff confirmed. Explore your project!

         Enter your project directory using cd ./..\..\.123
         Run npm run dev to start the dev server. q + ENTER to stop.
         Add frameworks like react or tailwind using astro add.

         Stuck? Join us at https://astro.build/chat
```

這樣就是完整的使用安裝精靈建立 Astro 專案了

### 第四步：啟動 Astro 專案

先 cd 到專案資料夾

執行`npm run dev`，這是啟動 Astro 本機開發伺服器

執行後出現`Local    http://localhost:4321/`

這時候就可以用瀏覽器打開 http://localhost:4321/ 

如果成功看到網站，就代表已經建立完成

要停止伺服器一樣回到終端輸入`Ctrl + C`即可

### 第五步：測試正式建置

執行`npm run build`，這會模擬正式部署時的建置流程

成功後通常會產生一個 dist 資料夾，裡面會有 Astro 轉換完成、準備部署的靜態網站檔案

### 第六步：建立 GitHub Repository

接下來就是打開 GitHub 新增一個新的 Repository

選擇 Public (我是免費帳號)，所以如果選私人的就沒辦法建立靜態網站ㄌ(除非有付費會員就可以XD)

以下項目先不要勾選：

```

Add a README file
Add .gitignore
Choose a license

```

點擊 Create repository 就建立好了

### 第七步：連接本機專案與 GitHub

Astro 建立專案時已經替完成第一次 Commit ，所以接下來就是連接倉庫

`git remote add origin https://github.com/你的帳號/倉庫名稱.git`

連接完之後可以執行`git remote -v`，來查看有沒有成功連接到倉庫

連接失敗不會出現任何資訊，連接成功會如下：

```
origin  https://github.com/Chkia0519/blog.git (fetch)
origin  https://github.com/Chkia0519/blog.git (push)
```

fetch：從 GitHub 下載更新

push：將本機版本上傳到 GitHub

origin：這個遠端儲存庫的簡稱

因為目前本機分支叫 master，我們先將它改成現在常用的 main

執行`git branch -M main`來更名，正常執行完成後不會出現東西(?

---

### 第八步：推送至 GitHub

執行`git push -u origin main`，完成第一次推送至遠端

git push：將本機提交推送到 GitHub

origin：剛才確認的 GitHub 遠端儲存庫

main：要推送的本機分支

-u：建立本機 main 與遠端 main 的追蹤關係

如果 GitHub 跳出登入或授權視窗，確認授權即可

推送完畢的時候可以到 GitHub 倉庫看有沒有資料出現了~

往後推送的時候用`git push`就可以了

---

### 第九步：設定 astro.config.mjs

打開 astro.config.mjs 這個檔案

調整內容為如下：

```
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://chkia0519.github.io',
  base: '/blog',
});
```

site：自己的 GitHub Pages 網站主網址

base：GitHub Repository (倉庫) 名稱，也就是 /blog

更改這些就好，有其他的設定不要動它

儲存檔案之後執行`npm run build`，出現 Complete! 就沒問題

### 第十步：設定 GitHub Actions 自動部署

因為我們上一步已經有修改 astro.config.mjs 

這時候要將先這個檔案 push 到雲端

在專案根目錄中建立：

```
.github/
└── workflows/
    └── deploy.yml
```

在 deploy.yml 部屬設定貼上以下程式碼：
```
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout your repository
        uses: actions/checkout@v7

      - name: Install, build, and upload your site
        uses: withastro/action@v6

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v5

```

這份程式碼設定是採用 Astro 官方目前文件中的 actions/checkout@v7、withastro/action@v6 與 actions/deploy-pages@v5

官方 Action 會從 package-lock.json 判斷你使用 npm，接著自動安裝套件、執行建置並上傳 dist

設定完畢後一樣`git push`到雲端，接下來要到 GitHub Repository 裡設定

```
Settings
→ Pages
→ Build and deployment
→ Source
→ GitHub Actions
```
